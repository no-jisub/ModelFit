- 두 소모품이 들어 있는 묶음 상품은 세 번째 소모품으로 세지 않고 두 소모품의 세트 상품으로 설명한다.
- 소모품을 사용하지 않는 제품은 카탈로그에서 제외한다.
- 모델 공식 확인 표시와 전체 페이지의 마지막 확인 날짜는 사용자 요청으로 화면에서 제거했다.
- 소모품 이름에는 `6개입` 같은 판매 구성 수량을 섞지 않고 실제 필터 명칭만 사용한다.
- 화면 수정은 단계별로 확인하고, 커밋도 기능별로 나누는 방식을 선호한다.

## 8. 테스트와 로컬 서버 주의사항

### E2E 포트

- 기본 E2E 원점은 `http://127.0.0.1:4322`다.
- `reuseExistingServer: false`이므로 이미 4322가 사용 중이면 테스트가 의도적으로 실패한다.
- 다른 프로세스를 무단 종료하지 말고 `outputs/` 아래에 임시 Playwright 설정을 만들어 4323 또는 4324처럼 별도 포트를 사용한다.
- 임시 설정은 테스트 후 삭제한다. `outputs/`는 `.gitignore`에 포함돼 있다.

### 4321 미리보기

- 현재 4321은 `astro preview`이며 `dist`를 제공한다.
- 소스만 수정해도 자동 반영되지 않는다.
- 반드시 `npm run build` 후 해당 프로젝트의 4321 미리보기 프로세스를 재시작한다.
- 재시작 전 `Get-NetTCPConnection`과 `Win32_Process.CommandLine`로 정확히 `C:\project\modelfit`의 Astro preview인지 확인한다.

### 줄바꿈

- Windows에서 Git이 `LF will be replaced by CRLF` 경고를 출력할 수 있다.
- `git diff`에 내용이 없는데 `git status`에 수정으로 남는 파일이 있을 수 있다.
- 사용자 변경을 지우기 위해 `git reset --hard`나 `git checkout --`를 사용하지 않는다.

## 9. 보안·배포 원칙

- `.env`, 서비스 계정 JSON, API 비밀키와 토큰을 커밋하지 않는다.
- Firebase 웹 API 키와 App Check 사이트 키는 공개 식별자이지만 서버 비밀키는 절대 프런트엔드에 넣지 않는다.
- Firestore 규칙 변경 시 문자열 검사만으로 끝내지 말고 Emulator 허용·거부 테스트를 유지한다.
- 배포 전 최소 `npm run check`, `npm run test:e2e`, `npm audit --audit-level=high`를 확인한다.
- 배포 후 운영 URL에서 검색 → 모델 → 소모품 → 구매 링크 흐름과 파트너스 고지를 확인한다.
